# llama.cpp (CUDA 13 / Windows x64)

Готовая сборка **llama.cpp** для Windows x64 с поддержкой аппаратного ускорения **NVIDIA CUDA 13.x**, оптимизированная для запуска и инференса современных LLM (включая модели Qwen 2.5 / 3.x, Llama, Mistral и др.) в режиме локального API-сервера или CLI.

---

## 🚀 Основные возможности

- **CUDA 13.x Acceleration:** Использование новейших библиотек cuBLAS и cuBLASLt (`cudart64_13.dll`, `cublas64_13.dll`, `cublasLt64_13.dll`) для максимальной производительности на GPU NVIDIA.
- **Flash Attention (`-fa`):** Поддержка Flash Attention для значительного ускорения инференса и снижения потребления VRAM при длинных контекстах.
- **Точность KV-кэша (`-ctk q8_0 -ctv q8_0`):** near-lossless `q8_0` для K и V (< 0.1 % perplexity, ≈34 КиБ/токен на 16 full-attention слоёв). Кодинг-конфиг `llamacpp-qwen38-27-4km.bat` использует `-c 196608` — весь KV (≈ 6.5 ГБ) целиком в VRAM с запасом ~2 ГБ на карту сверх проверенного `-c 262144` (`-ts 17,13`, prompt processing ~960 tok/s, VRAM ~14.9 / 14.7 ГБ на карту). Несжатый `-ctk f16` на этой паре 16 ГБ переполняет GPU0 и спиливает вычисления на CPU уже при `-c > ~98304`, поэтому не используется.
- **Multi-GPU / Tensor Split (`-ts`):** Распределение слоев и вычислений между несколькими видеокартами (например, Dual GPU сетапы).
- **MTP / Speculative Decoding (`--spec-type draft-mtp`):** Поддержка Multi-Token Prediction для ускорения генерации ответов.
- **Гибридная архитектура модели (Transformer + SSM):** `Qwen3.8-27B-UD-Q4_K_M.gguf` использует полное внимание (с KV-кэшем) только в каждом 4-м слое, остальные слои — SSM-состояние фиксированного размера, не растущее с длиной контекста. Нативный лимит модели — 262144 токена. На данной связке 2x16GB GPU (см. [конфигурацию тестового стенда](#-конфигурация-тестового-стенда)) без NVLink весь контекст помещается в VRAM: кодинг-конфиг `llamacpp-qwen38-27-4km.bat` использует `-ctk q8_0 -ctv q8_0`, `-c 196608`, `-ub 256`, `-ts 17,13` (KV ≈ 6.5 ГБ, запас ~2 ГБ на карту). Тот же бюджет вмещает и полный `-c 262144` (проверено: prompt processing ~960 tok/s, без `retrying without pipeline parallelism`, запас VRAM ~1.4–1.6 ГБ на карту) — `-c 196608` взят ради дополнительного запаса. Если в логе появится `retrying without pipeline parallelism` или `cudaMalloc failed` — понижать `-c` по ступеням (`196608 → 180224 → 163840`) либо ослабить KV до `-ctv q4_0`.
- **Кастомные шаблоны чата (`configs/qwen38.jinja`):** Полная поддержка Jinja-шаблонов для точного форматирования сообщений и системных инструкций.
- **Совместимость с OpenAI API:** Встроенный веб-сервер предоставляет REST API, совместимый с OpenAI (`/v1/chat/completions`, `/v1/models`, `/v1/completions`), веб-интерфейс и эндпоинты для интеграции с клиентами (Open WebUI, SillyTavern, Continue, cline, Cursor и др.).

## ⚡ Быстрый старт

### 1. Подготовка модели

Поместите нужную `.gguf` модель в директорию `models/` (или используйте уже имеющиеся).

### 2. Запуск сервера

Запустите командный файл (из корня проекта или двойным кликом по файлу):

```bat
configs\llamacpp-qwen38-27-4km.bat
```

После запуска сервер будет доступен по адресу:

- **Web UI & API:** `http://127.0.0.1:1234`
- **OpenAI Endpoint:** `http://127.0.0.1:1234/v1/chat/completions`
- **Health Check:** `http://127.0.0.1:1234/health`

## 🛠️ Вспомогательные утилиты

- **`llama-cli.exe`** — Интерактивный терминальный чат:
  ```cmd
  .\llamacpp\llama-cli.exe -m .\models\Qwen3.8-27B-UD-Q4_K_M.gguf -ngl 99 -c 8192 -p "Привет! Расскажи о себе."
  ```
- **`llama-bench.exe`** — Тестирование производительности (prompt processing и text generation speed):
  ```cmd
  .\llamacpp\llama-bench.exe -m .\models\Qwen3.8-27B-UD-Q4_K_M.gguf -ngl 99 -n 128 -p 512
  ```
- **`llama-quantize.exe`** — Преобразование моделей в различные кванты (Q4_K_M, Q5_K_M, Q8_0 и др.):
  ```cmd
  .\llamacpp\llama-quantize.exe .\models\model-f16.gguf .\models\model-Q4_K_M.gguf Q4_K_M
  ```

## 💻 Конфигурация тестового стенда

Параметры в примере конфигурации (`-ts 17,13`, `-t 16` / `--threads-batch 16`, `-c 196608`, `-ub 256`, `-ctk q8_0 -ctv q8_0`, `--no-mmproj` и др.) подобраны и проверены на следующем железе (полный `-c 262144` с теми же прочими значениями проверен на нём же):

> `-ts 17,13` намеренно смещает слои на GPU0 (PCI-шина 1): в режиме `-sm layer` KV-кэш, кэш SSM-состояния linear-attention слоёв и compute-буферы pipeline parallelism оседают на старшей карте, поэтому равный `-ts` даёт перекос ~3 ГБ. При `-c 262144` это выравнивает карты до ~14.9 / 14.7 ГБ. Значение подбирается по факту — сверяйте занятость карт в `nvidia-smi` после старта и двигайте на ±1. Если в `llama-server.log` появляется `retrying without pipeline parallelism`, VRAM не хватает — снизьте `-c` или `-ctv` до `q4_0`.

| Компонент   | Значение                                                                 |
| :---------- | :----------------------------------------------------------------------- |
| **CPU**     | AMD Ryzen 9 9950X (16 ядер / 32 потока)                                  |
| **RAM**     | 64 ГБ DDR5-5600                                                          |
| **GPU**     | 2× NVIDIA GeForce RTX 5060 Ti 16GB (32 ГБ VRAM суммарно, без NVLink/P2P) |
| **ОС**      | Windows 11 Pro x64                                                       |
| **Драйвер** | Актуальный драйвер NVIDIA с поддержкой CUDA 13.x                         |

При другой конфигурации (иное число ядер CPU, другой объём/распределение VRAM) значения `-ts`, `-t`, `--threads-batch` и `-c` стоит пересчитать под своё железо.

### Минимальные требования

- **ОС:** Windows 10 / 11 (x64)
- **GPU:** Видеокарта NVIDIA (рекомендуется с поддержкой архитектуры Pascal и новее: RTX 20xx/30xx/40xx/50xx)
- **Драйвер:** Актуальный драйвер NVIDIA с поддержкой CUDA 13.x
